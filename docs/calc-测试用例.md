# calc 工具测试用例（8 条）+ 缺陷单

被测对象：`agent/tools.py` 里的 `calc` 工具（算术表达式求值，白名单字符 + 空 `__builtins__`）
执行命令：`python -m pytest tests/test_calc_cases.py -v`
结果：**9 条用例 → 8 passed, 1 xfailed**；全项目 **22 passed, 1 xfailed**

## 二、缺陷单

### BUG-001 · calc 浮点精度未处理（未修复，已知限制）

| 字段 | 内容 |
|---|---|
| 编号 | BUG-001 |
| 模块 | `agent/tools.py` → `_calc` |
| 严重程度 | 低（不影响功能，影响展示/对账） |
| 优先级 | 低 |
| 复现步骤 | 调用 `calc`，参数 `expression="0.1+0.2"` |
| 期望结果 | `0.3` |
| 实际结果 | `0.30000000000000004`（Python 二进制浮点固有误差） |
| 影响 | 金额/比例类计算展示不友好；下游若按字符串比较会误判 |
| 建议修复 | 结果按 `Decimal` 计算或 `round(value, 10)`；对外输出前统一格式化 |
| 当前处理 | 用例标记 `xfail(strict=True)`，记录事实但不阻断 CI |

### BUG-002 · calc 表达式含前导空格导致崩溃（已修复）

| 字段 | 内容 |
|---|---|
| 编号 | BUG-002 |
| 严重程度 | 中（用户正常输入就会触发） |
| 优先级 | 高 |
| 复现步骤 | 调用 `calc`，参数 `expression=" 1 + 2 "` |
| 期望结果 | 返回 3（空格应当被忽略） |
| 实际结果 | 抛 `ToolError: cannot evaluate expression: unexpected indent (line 1)` |
| 根因 | 白名单正则允许空格，但 `compile(expr, "<calc>", "eval")` 遇到前导空格报 `IndentationError` |
| 修复 | `_calc` 入口先 `expression.strip()`，再做白名单校验与编译 |
| 回归 | TC-02 通过；全量 22 passed, 1 xfailed |

## 三、面试时怎么讲这两条

一句话版本：

> 我给自己的 `calc` 工具设计了 8 条用例，用等价类、边界值和异常路径覆盖。跑出来发现两个问题：一个是前导空格会让表达式编译崩掉（这个我修了，加了 `strip()` 并补了回归用例）；另一个是浮点精度，`0.1+0.2` 返回 `0.30000000000000004`，这个属于 Python 浮点固有误差，我按缺陷单记录、标 xfail，等确定业务口径再改。

这段话里同时包含了：用例设计方法、缺陷发现、缺陷单字段、修复与回归、已知限制的处置——面试官听到这五点，就知道你不是"只会点点点"的那种实习生。
